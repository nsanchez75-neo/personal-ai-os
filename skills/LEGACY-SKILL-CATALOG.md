## Normalization rule

These are **legacy candidates**, not yet canonical skills. Before moving any skill into `skills/`:

1. assign an explicit capability contract;
2. remove provider-specific assumptions from the portable core;
3. identify dependencies;
4. add or normalize evaluation cases;
5. define required tools and least privilege;
6. define memory/knowledge inputs and outputs;
7. define failure modes and HITL boundaries;
8. verify that an existing canonical skill does not already cover the same capability.

Duplicate trees in the uploaded archive are intentionally not copied.
