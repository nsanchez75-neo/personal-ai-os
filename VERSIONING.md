# VERSIONING POLICY

Use semantic project versions for stable milestones.

Format:
`MAJOR.MINOR`

Examples:
- v0.1 — foundation
- v0.2 — CEO Brain initial implementation
- v0.3 — orchestration prototype
- v1.0 — first validated operational release

Every meaningful release should update:
- PROJECT-CONTEXT.md
- CHANGELOG.md
- relevant DECISIONS.md entries

Git commits should be atomic and descriptive.
