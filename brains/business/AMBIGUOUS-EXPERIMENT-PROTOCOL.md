# BUSINESS BRAIN — AMBIGUOUS EXPERIMENT PROTOCOL v0.1

## Purpose

Prevent over-updating the Business Brain when experiment evidence is noisy, incomplete, conflicting, contaminated or insufficient for the decision stakes.

This protocol operationalizes Evaluation Test 14 and is a decision aid, not a universal statistical threshold.

## Evidence states

### E0 — Insufficient evidence
Use when the test cannot answer the hypothesis because sample/context/time is inadequate, the measurement is too weak, or the observed behavior is too sparse for the stakes.

Action:
- do not update the core belief materially;
- identify the missing information;
- extend, redesign or repeat the test if decision value justifies it.

### E1 — Conflicting evidence
Use when credible signals point in different directions.

Action:
- separate segments, channels, cohorts, time periods or measurements;
- investigate whether the conflict reflects heterogeneity or measurement differences;
- avoid averaging away meaningful disagreement;
- run a discriminating follow-up test.

### E2 — Invalid / contaminated
Use when execution, instrumentation, sample selection, external events, leakage, confounding or protocol violations make the result unreliable.

Action:
- do not treat the result as evidence for or against the hypothesis;
- document the contamination;
- repair the test design/instrumentation;
- repeat if decision value justifies it.

### E3 — Weak support
Use when the result is directionally consistent with the hypothesis but evidence strength is limited.

Action:
- make only a proportional belief update;
- avoid irreversible commitments;
- seek replication or stronger behavioral/economic evidence.

### E4 — Strong support
Use when evidence is sufficiently credible, relevant and repeatable for the stakes.

Action:
- update the model proportionally;
- consider scaling or broader validation;
- preserve guardrails and review triggers.

### E5 — Disconfirming evidence
Use when credible evidence materially contradicts a critical hypothesis.

Action:
- update against the hypothesis;
- identify which assumption failed;
- stop, pivot or redesign when the failed assumption is foundational;
- do not continue solely because resources were already spent.

## Evidence-strength dimensions

Evaluate:
- decision stakes;
- sample/context adequacy;
- measurement reliability;
- baseline quality;
- effect magnitude or practical relevance;
- consistency across observations;
- segment/cohort consistency;
- confounders;
- external events;
- replication;
- time horizon;
- behavioral vs stated evidence.

Do not invent precision when the evidence does not support it.

## Decision matrix

| Evidence state | Core belief update | Typical next move |
|---|---|---|
| E0 Insufficient | Minimal / none | Gather information or extend test |
| E1 Conflicting | None until explained | Segment, diagnose, discriminating test |
| E2 Invalid | None | Repair and repeat |
| E3 Weak support | Small/proportional | Replicate or run bounded next test |
| E4 Strong support | Material/proportional | Scale with guardrails if economics/capacity permit |
| E5 Disconfirming | Material against | Stop/pivot/redesign when critical |

## Mandatory distinction

An ambiguous result is not automatically a failure.

The Business Brain must distinguish:
1. uncertainty about the hypothesis;
2. uncertainty about measurement;
3. uncertainty caused by conflicting segments;
4. uncertainty caused by inadequate test design.

## Pre-decision checklist

Before converting an experiment into a durable business-model update, ask:

- What exactly was predicted?
- What was actually observed?
- Which evidence is behavioral?
- Is the test valid?
- What could explain the result besides the hypothesis?
- Is the result consistent across relevant contexts?
- What evidence would change the current interpretation?
- What is the downside of acting too early?
- What is the cost of waiting?
- What is the smallest next test that reduces the most important uncertainty?

## Learning rule

The model update must preserve:
- prior belief;
- new evidence;
- interpretation;
- confidence/change in confidence;
- decision consequence;
- follow-up test.

Never rewrite historical evidence to make the new interpretation appear inevitable.
